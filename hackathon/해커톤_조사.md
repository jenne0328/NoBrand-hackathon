# AI 트렌드 정보 수집 및 스터디 웹앱 — 해커톤 조사

조사일: 2026-11-07  
목표: AI 관련 정보를 빠르게 선별하고, 팀이 함께 읽고 학습 결과를 남기는 웹앱의 MVP 방향을 정한다.

## 1. 유사 서비스 3개

| 서비스 | 좋은 점 | 아쉬운 점 |
| --- | --- | --- |
| [Feedly AI](https://feedly.com/ai) | RSS·뉴스·뉴스레터를 AI Feed로 수집하고, AI 모델 및 AND/OR/NOT 조건으로 노이즈를 줄인다. ### 경쟁 서비스에서 얻을 포인트

- Feedly/Inoreader처럼 **개인화 수집·필터링**을 제공하되, 학생·소규모 스터디가 바로 쓸 수 있도록 핵심 기능을 단순화한다.
- NotebookLM처럼 **읽기 결과를 학습 산출물**로 바꾸되, 수집부터 토론·복습까지 한 흐름으로 연결한다.

## 2. 실제 사용자의 불편함 5가지

1. **정보 과잉 때문에 중요한 변화만 골라내기 어렵다.** 모델 출시·논문·제품 업데이트·SNS 반응이 동시에 쏟아져 피드 소비 시간이 과도해진다. 관심 분야·직무 맥락에 맞춘 개인화와 중요도 판단이 부족한 것이 원인이다.  
   → 관심 토픽/직무 기반 피드, 일·주간 핵심 3건, `왜 중요한가` 한 줄 요약을 제공한다. ([Henley Business School 조사](https://assets.henley.ac.uk/v3/fileUploads/The-AI-High-FOBO-report_FINAL_Jun-25.pdf))

2. **출처 신뢰도와 원문 검증에 시간이 든다.** 마케팅성 글·재인용 기사·AI 생성 요약이 섞여 있어 사실성·최신성을 직접 원문에서 재확인해야 한다.  
   → 원문 링크·발행일·출처 유형(공식/논문/언론/커뮤니티) 배지와 인용 근거, 신뢰도 필터를 제공한다. ([Stack Overflow 2024 AI 조사](https://survey.stackoverflow.co/2024/ai))

3. **새 소식이 내 업무에 어떤 영향인지 판단하기 어렵다.** 기능 소개만으로는 적용 대상, 학습 우선순위, 비용·성능·보안 제약을 파악하기 어렵다.  
   → `누구에게 유용한가`, 적용 사례, 예상 비용/제약, 난이도 태그, 개인 프로젝트 연결 메모를 제공한다. ([Notion AI Engineering Survey](https://www.notion.com/lp/ai-engineering-survey))

4. **혼자 읽고 끝나 학습이 축적되지 않는다.** 북마크만 쌓이고, 이해 여부 확인·복습·자기 언어로 정리하는 과정이 빠진다.  
   → 링크별 3줄 요약 → 핵심 개념 카드 → AI 퀴즈 → 오답/복습 알림 → 개인 학습 로그로 연결한다.

5. **팀 스터디의 공통 맥락과 참여를 맞추기 어렵다.** 각자 다른 자료를 가져오고 읽은 깊이가 달라 발표 준비가 중복된다. 누가 무엇을 읽고 토론했는지도 보이지 않는다.  
   → 팀 컬렉션, 읽기/발표 담당 배정, 댓글·질문·투표, 주간 스터디 보드와 요약 리포트를 제공한다. ([Atlassian State of Developer Experience 2026](https://wac-cdn.atlassian.com/teams/software-development/state-of-developer-experience-2026))

## 3. 웹페이지·배포·Supabase·skill·plugin으로 만드는 핵심 기능 3가지

### 1) 개인화 AI 트렌드 레이더

- **사용 흐름:** 웹에서 키워드·관심 분야를 고르면 RSS/API로 모은 논문·뉴스·릴리스 노트를 카드로 보여주고, 중요도·난이도·출처로 필터링한다.
- **구현:** Supabase에 사용자 프로필, 관심 태그, 북마크, 읽음 상태를 저장한다. Auth와 RLS(Row Level Security)로 사용자별 데이터를 분리한다.
- **가치:** `무엇을 봐야 할지` 찾는 시간을 줄이고, 팀원별 맞춤 피드를 제공한다.
- **근거:** [Supabase Auth](https://supabase.com/docs/guides/auth), [Supabase Database](https://supabase.com/docs/guides/database/overview)

### 2) 같이 읽고 끝내는 스터디 룸

- **사용 흐름:** 각 트렌드 카드에서 팀 메모, 질문, 이해도 투표, 3문항 퀴즈, 주간 학습 현황을 제공한다.
- **구현:** Supabase Realtime private channel과 RLS를 이용해 같은 팀에만 댓글·투표·진행률 변경을 실시간 전송한다.
- **가치:** 단순 링크 공유를 `읽기 → 토론 → 이해 확인`의 학습 루프로 바꾼다.
- **근거:** [Realtime DB 변경 구독](https://supabase.com/docs/guides/realtime/subscribing-to-database-changes), [Realtime 권한 관리](https://supabase.com/docs/guides/realtime/authorization)

### 3) Codex 주간 브리핑 생성·발행 자동화

- **사용 흐름:** `AI Trend Brief` skill이 이번 주 저장 자료를 출처 링크와 함께 5줄 요약, 핵심 용어, 토론 질문으로 정리한다. 필요하면 웹앱의 자료·팀·주간 목표를 읽는 MCP plugin을 연결한다.
- **구현:** skill은 반복 브리핑의 입력·선별·출력 형식을 정의하고, plugin/MCP는 웹앱 데이터 접근을 담당한다. Git 저장소를 Vercel에 연결해 커밋·PR마다 Preview URL을 만들어 데모와 피드백을 빠르게 반복한다.
- **가치:** 수작업 요약·공지 시간을 줄이고, 해커톤에서 실제 사용 흐름을 한 번에 시연할 수 있다.
- **근거:** [OpenAI Skills](https://developers.openai.com/plugins/concepts/skills), [OpenAI Plugin architecture](https://developers.openai.com/plugins/concepts/plugins), [Vercel Deployments](https://vercel.com/docs/deployments)

## 권장 MVP 우선순위

| 우선순위 | 범위 | 해커톤 데모 포인트 |
| --- | --- | --- |
| 1 | 개인화 트렌드 레이더 | 가입 → 관심사 선택 → 맞춤 트렌드 카드와 저장 |
| 2 | 스터디 룸 | 같은 카드에 팀원이 실시간으로 메모·투표·퀴즈 |
| 3 | 주간 브리핑 자동화 | 저장된 자료가 출처 포함 스터디 브리핑으로 변환 |

권장 일정은 첫날 수집·저장·대시보드, 둘째 날 실시간 협업, 마지막에 브리핑 자동화와 배포 시연이다.
