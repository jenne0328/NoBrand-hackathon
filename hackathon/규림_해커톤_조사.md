# AI 트렌드 정보 대시보드 및 스터디 웹앱 — 해커톤 조사

- 조사일: 2026-11-07
- 주제: AI 트렌드 정보 대시보드(수집) 및 스터디 웹앱
- 조사 범위: 유사 서비스, 대상 사용자의 불편, 웹페이지·배포·Supabase·Skill·Plugin 기반 핵심 기능

## 한눈에 보는 결론

이 서비스의 가장 좋은 차별화 방향은 **여러 출처의 AI 정보를 자동 수집하고, 출처가 보이는 요약을 제공한 뒤, 선택한 자료를 팀 스터디·토론·퀴즈로 즉시 전환하는 것**이다.

해커톤 MVP는 다음 흐름에 집중하는 것이 적절하다.

> 새 AI 정보 자동 수집 → 대시보드에서 필터·선택 → 출처 기반 요약 확인 → 스터디와 퀴즈 생성 → 팀 진행률 기록 → 대화형 플러그인에서 검색·저장·시작

## 1. 비슷한 서비스 3개

> 아래의 아쉬운 점은 각 서비스가 공개한 기능 범위를 이번 해커톤 주제와 비교해 도출한 평가다.

### 1.1 Feedly AI

- 링크: [Feedly AI 공식 소개](https://feedly.com/ai), [AI Feed 생성 방법](https://docs.feedly.com/article/807-how-to-create-ai-feeds)
- 성격: 여러 웹 소스에서 특정 주제·기업·트렌드 정보를 수집하고 AI로 분석·우선순위화하는 리서치/인텔리전스 서비스

**좋은 점**

- 수많은 출처의 정보를 한곳에 모아 탐색 시간을 줄인다.
- `AND·OR·NOT`, 소스 범위 지정, 사전 학습된 개념 모델을 이용해 맞춤 피드를 만들 수 있다.
- 저장한 피드가 지속적으로 새 정보를 수집하므로 트렌드 모니터링에 적합하다.
- 결과를 공유하거나 외부 도구와 연동해 팀 단위로 활용할 수 있다.

**아쉬운 점**

- 범용 시장·위협 인텔리전스 성격이 강해 AI 학습에 특화된 분류 체계와 학습 경로는 상대적으로 약하다.
- 좋은 피드를 만들려면 사용자가 조건과 소스를 직접 설계하고 계속 다듬어야 한다.
- 수집·우선순위화에는 강하지만 퀴즈, 진도, 스터디 토론 같은 학습 관리 기능은 핵심 범위가 아니다.

### 1.2 Hugging Face Daily Papers / Trending Papers

- 링크: [Daily Papers](https://huggingface.co/papers), [Trending Papers 공식 소개](https://huggingface.co/changelog/trending-papers)
- 성격: AI 연구 논문을 일·주·월 단위로 보여주고 커뮤니티 반응과 GitHub 활동을 바탕으로 인기 연구를 탐색하게 해주는 서비스

**좋은 점**

- 최신 AI 논문을 한곳에서 빠르게 확인할 수 있다.
- 일간·주간·월간 보기, 검색, 커뮤니티 업보트 등 탐색 장치가 명확하다.
- GitHub 스타 활동 기반 순위와 관련 코드 저장소·arXiv 원문을 연결해 논문에서 구현까지 추적하기 쉽다.
- 요약, 저자, 기관 등 핵심 메타데이터가 함께 제공되어 스터디 자료 후보를 찾기 좋다.

**아쉬운 점**

- 논문 중심이어서 제품 출시, 기업 동향, 정책, 개발 도구, 산업 사례 등 폭넓은 AI 트렌드는 충분히 다루지 않는다.
- GitHub 스타 기반 인기도가 학술적 중요성이나 개인의 학습 목표와 반드시 일치하지는 않는다.
- 팀별 커리큘럼, 퀴즈, 학습 진도와 같은 스터디 운영 기능은 핵심 화면에서 제공되지 않는다.

### 1.3 DeepLearning.AI — The Batch

- 링크: [The Batch](https://www.deeplearning.ai/the-batch), [공식 소개](https://www.deeplearning.ai/the-batch/about)
- 성격: 주요 AI 뉴스·연구·제품·비즈니스·사회 이슈를 전문가 관점으로 선별해 쉽게 설명하는 주간 뉴스레터/아카이브

**좋은 점**

- 영향이 작거나 중복된 기사를 걸러내 중요한 소식만 제공해 정보 과부하를 줄인다.
- 연구, 제품, 비즈니스, 하드웨어, 커리어 등 AI 생태계를 폭넓게 다룬다.
- 초보자도 이해하기 쉬운 설명과 추가 자료 링크가 있어 입문 스터디 자료로 좋다.
- 단순 헤드라인을 넘어 “왜 중요한지”에 대한 해설이 있어 토론 주제를 만들기 쉽다.

**아쉬운 점**

- 주간 발행이므로 실시간 또는 일간 트렌드 감지에는 한계가 있다.
- 편집자가 선정한 동일 콘텐츠를 읽는 구조라 관심 분야별 개인화 대시보드 기능이 약하다.
- 여러 출처를 직접 비교하거나 트렌드 변화를 차트로 관찰하기 어렵다.
- 특정 기사에서 바로 팀 스터디·퀴즈·진도 추적으로 이어지는 통합 흐름은 뚜렷하지 않다.

### 유사 서비스에서 얻는 기회

Feedly의 **다중 출처 자동 수집**, Hugging Face의 **기간별 인기 탐색과 원문·코드 연결**, The Batch의 **쉬운 요약과 학습 맥락**을 결합하되, 여기에 **팀 북마크·토론·퀴즈·진도 관리**를 하나의 흐름으로 연결하면 차별화할 수 있다.

## 2. 실제 사용자가 겪는 불편 5가지

### 2.1 AI 정보가 너무 빠르고 많이 쏟아져 핵심만 따라가기 어렵다

- **상황:** 개발자·PM·디자이너·학생이 논문, 모델 출시, 벤치마크, 정책, 튜토리얼, SNS를 각각 확인한다.
- **원인:** AI 정보의 양과 변화 속도가 개인이 소화할 수 있는 수준을 넘어섰고, 메시지·회의·알림으로 집중력도 계속 분산된다.
- **결과:** 중요한 소식을 놓치거나 여러 채널을 훑고도 무엇이 중요한지 판단하지 못한다.
- **근거:** Stanford AI Index에 따르면 AI 관련 논문은 2013년 약 10.2만 건에서 2023년 24.2만 건 이상으로 증가했다. [Stanford AI Index Report 2025](https://hai.stanford.edu/assets/files/hai_ai_index_report_2025.pdf), [Microsoft Work Trend Index — Breaking down the infinite workday](https://www.microsoft.com/en-us/worklab/work-trend-index/breaking-down-infinite-workday)
- **구분:** 정보량 증가와 업무 중단은 근거 기반 사실이며, 이것이 AI 트렌드 탐색자의 피로·누락으로 연결된다는 부분은 검증할 제품 가설이다.

### 2.2 AI 요약을 그대로 믿기 어려워 원문을 다시 검증해야 한다

- **상황:** 뉴스 요약, SNS 게시물, AI 생성 설명을 발견해도 실제 발표·논문·문서와 일치하는지 다시 확인한다.
- **원인:** AI 출력은 그럴듯해도 세부적으로 틀릴 수 있고, 출처·발행일·버전·이해관계가 빠질 수 있다.
- **결과:** 정보 수집 시간을 줄이려고 AI를 쓰지만 원문 대조와 교차 검증에 추가 시간이 들고, 잘못된 정보를 공유할 위험도 생긴다.
- **근거:** Stack Overflow 2025 조사에서 AI 출력 정확도를 불신한다는 개발자(46%)가 신뢰한다는 개발자(33%)보다 많았고, 강하게 신뢰한다는 응답은 3%였다. [Stack Overflow 2025 Developer Survey — AI](https://survey.stackoverflow.co/2025/ai)
- **구분:** 신뢰도 수치는 근거 기반 사실이며, 뉴스·학습 콘텐츠에도 같은 검증 부담이 생긴다는 부분은 사용자 인터뷰로 확인할 제품 가설이다.

### 2.3 내 역할과 수준에 맞는 정보를 실제 학습 순서로 바꾸기 어렵다

- **상황:** 같은 이슈라도 개발자는 구현 예제, PM은 활용 사례와 비용, 디자이너는 UX 변화, 학생은 개념과 선행지식이 필요하다.
- **원인:** 일반 피드와 검색 결과는 인기도·최신성 중심이며 역할, 기존 지식, 목표, 가용 시간을 충분히 반영하지 못한다.
- **결과:** 링크는 많이 저장하지만 무엇부터 읽을지 정하지 못하고, 너무 어렵거나 쉬운 자료를 만나 학습 흐름이 끊긴다.
- **근거:** MOOC 연구는 학습자의 특성·목표·자기조절 능력이 서로 다르며 목표 설정과 개인 학습 경로 지원이 필요하다고 설명한다. [An investigation of self-regulated learning in a novel MOOC platform](https://link.springer.com/article/10.1007/s12528-022-09346-x)
- **구분:** 학습자별 차이와 자기조절 지원 필요성은 연구 근거이며, 역할 기반 AI 피드가 이를 해결할 수 있다는 것은 제품 가설이다.

### 2.4 링크·메모·토론이 여러 도구에 흩어져 팀 지식으로 남지 않는다

- **상황:** 개인 북마크, Slack/메신저, Notion, 문서, 브라우저 탭에 자료와 의견이 분산된다.
- **원인:** 팀원이 서로 다른 도구와 분류 방식을 쓰고, 원문·요약·메모·토론·학습 상태가 하나의 항목으로 연결되지 않는다.
- **결과:** 이미 누군가 조사한 주제를 다시 찾거나 중복 조사하며, 새 팀원은 과거 맥락과 결론을 파악하기 어렵다.
- **근거:** Atlassian의 2024 팀 조사에서는 지식 노동자의 55%가 사내 정보를 찾기 어렵고, 50%가 다른 팀의 같은 작업을 뒤늦게 알았으며, 56%가 팀마다 다른 추적 방식 때문에 협업이 어렵다고 답했다. [Atlassian State of Teams 2024](https://www.atlassian.com/blog/state-of-teams-2024)
- **구분:** 정보 탐색·중복·도구 분산은 근거 기반 사실이며, AI 스터디 팀에서의 구체적 양상은 대상 사용자 인터뷰로 검증할 가설이다.

### 2.5 저장하거나 가입해도 꾸준히 학습하고 토론하기 어렵다

- **상황:** 처음에는 링크와 목표를 모으지만 업무가 바빠지면 읽기·정리·발표·복습이 밀린다.
- **원인:** 시간 부족, 목표·진도 관리 부족, 피드백 부재, 낮은 사회적 상호작용과 고립감이 학습 지속을 방해한다.
- **결과:** “나중에 읽기” 목록만 늘고 참여율이 떨어지며, 읽은 내용도 토론이나 산출물로 이어지지 않는다.
- **근거:** 21개 연구를 검토한 문헌고찰은 MOOC 중도 이탈 요인을 과정 특성, 인지·정서, 학습 행동 등으로 분류했다. [Take a MOOC and then drop](https://www.sciencedirect.com/science/article/pii/S2405844023024271). 온라인 학습의 상호작용 부족과 고립감, 동료 상호작용의 효과를 다룬 검토도 있다. [Supporting social interactions to improve MOOC participants’ learning outcomes](https://www.frontiersin.org/journals/education/articles/10.3389/feduc.2024.1345205/full)
- **구분:** 시간·동기·상호작용이 학습 지속에 영향을 준다는 점은 연구 근거이며, 알림·진도판·동료 피드백의 실제 효과는 구현 후 검증할 가설이다.

### 문제 우선순위

MVP에서 먼저 해결할 문제는 **① 정보 과부하, ② 출처 신뢰성, ④ 팀 지식 분산**이다. 이는 `자동 수집 → 출처가 보이는 요약 → 팀 단위 저장·토론`이라는 하나의 사용 흐름으로 연결된다. 개인화와 학습 지속 기능은 역할 태그, 읽음 상태, 주간 목표 정도로 작게 시작한다.

## 3. 구현 가능한 핵심 기능 3가지

### 권장 전체 구조

- **웹페이지:** 카드형 AI 트렌드 피드, 검색·필터, 스터디 공간
- **배포:** 플러그인 데모가 핵심이면 Sites 기반 클라우드 플러그인, 독립 웹앱이 핵심이면 Vercel + Supabase
- **Supabase:** Auth, Postgres, RLS, Realtime, Cron, Edge Functions, pgvector
- **Skill:** 수집 → 요약 → 출처 검증 → 스터디 질문 생성의 반복 가능한 에이전트 작업 절차
- **Plugin:** 대화에서 검색·저장·퀴즈 생성·진행 상태 조회를 실행하는 MCP 도구와 인터랙티브 뷰

> 해커톤에서는 Sites와 Vercel을 동시에 운영하지 않고 시연 목표에 따라 하나를 고르는 편이 좋다.

### 3.1 자동 수집·요약되는 개인화 AI 트렌드 피드

**사용자 가치**

여러 뉴스레터, 블로그, 논문, GitHub를 돌아다니지 않고 새 AI 소식을 한 화면에서 확인하며, 중복 기사를 묶고 핵심만 빠르게 파악한다.

**기능 흐름**

1. 관리자가 RSS/API/GitHub Releases 등 허용된 소스를 등록한다.
2. Supabase Cron이 주기적으로 Edge Function을 호출한다.
3. 신규 항목을 가져와 URL 기준으로 중복을 제거하고 원문 링크, 출처, 날짜, 태그를 저장한다.
4. AI가 3줄 요약, 난이도, 관련 직군, 핵심 키워드를 생성한다.
5. 웹 대시보드가 최신순·주제별·직군별 카드 피드를 보여준다.
6. 사용자가 북마크하거나 이번 주 스터디에 추가한다.

**기술 역할**

| 기술 | 역할 |
|---|---|
| 웹페이지 | 트렌드 카드, 출처 링크, 필터, 북마크 UI |
| 배포 | Sites 비공개 배포 또는 Vercel Preview/Production 배포 |
| Supabase | 소스·기사·태그·북마크 저장, Cron/Edge Functions 수집, Auth/RLS 보호 |
| Skill | 신뢰도 확인, 중복 판별, 요약 형식, 원문 링크 보존 규칙 |
| Plugin | “이번 주 생성형 AI 뉴스 5개”, “이 글 저장” 같은 대화형 도구 |

**MVP 범위**

- 공식 AI 기업 블로그 RSS, arXiv API, GitHub Releases의 3개 소스 유형
- 1시간 또는 1일 간격 수집
- URL 기반 중복 제거
- 제목·3줄 요약·출처·태그 표시
- 북마크와 스터디 추가

**난이도와 리스크**

- 난이도: 중
- 원문 크롤링은 robots.txt, 이용약관, 저작권, HTML 구조 변경 위험이 있으므로 RSS·공식 API·제목/초록 중심으로 시작한다.
- AI 요약의 환각을 줄이기 위해 원문 링크와 발행일을 항상 표시한다.
- Edge Function은 짧고 멱등적으로 만들고, 모든 공개 스키마 테이블에 RLS를 적용하며 secret/service role 키를 브라우저에 노출하지 않는다.

공식 참고: [Supabase Cron](https://supabase.com/docs/guides/cron), [Scheduling Edge Functions](https://supabase.com/docs/guides/functions/schedule-functions), [Supabase Edge Functions](https://supabase.com/docs/guides/functions), [Vercel Deployments](https://vercel.com/docs/deployments)

### 3.2 저장한 자료를 학습 자산으로 바꾸는 AI 스터디룸

**사용자 가치**

읽을 링크만 쌓이는 문제를 줄이고, 저장 자료를 요약 노트·질문·퀴즈·토론 안건으로 바꿔 실제 학습과 팀 토론까지 연결한다.

**기능 흐름**

1. 트렌드 카드 여러 개를 선택해 스터디 세션을 만든다.
2. AI가 공통 주제 요약, 용어 설명, 토론 질문, 퀴즈를 생성한다.
3. 콘텐츠 임베딩을 저장해 의미 기반 검색을 제공한다.
4. 팀원이 답변·메모·완료 상태를 기록한다.
5. Supabase Realtime으로 참여 현황이나 새 메모를 반영한다.
6. 종료 후 핵심 배움과 다음 학습 주제를 정리한다.

**기술 역할**

| 기술 | 역할 |
|---|---|
| 웹페이지 | 세션, 읽기 목록, 공동 메모, 퀴즈, 진행률 UI |
| 배포 | Preview URL에서 권한·퀴즈 흐름을 검증한 뒤 Production 반영 |
| Supabase | 세션·멤버·메모·응답, Realtime, pgvector, Auth와 소유권 기반 RLS |
| Skill | 자료 수준에 맞춘 요약·질문·퀴즈 생성 절차와 출력 포맷 |
| Plugin | “저장한 글로 30분 스터디 생성”, “RAG 관련 내용 검색” |

**MVP 범위**

- 최대 5개 자료로 스터디 1개 생성
- 통합 요약, 토론 질문 3개, 객관식 퀴즈 5개
- 팀원별 완료 체크와 간단한 공동 메모
- 제목/요약 임베딩 기반 의미 검색
- Realtime은 메모 또는 진행률 하나에만 적용

**난이도와 리스크**

- 난이도: 중상
- 콘텐츠와 질의 임베딩에 같은 모델을 사용한다.
- 퀴즈마다 정답의 근거가 되는 원문 링크를 연결한다.
- `authenticated` 여부만 확인하지 말고 `study_members` 등 멤버십/소유권 조건을 포함한 RLS 정책을 둔다.

공식 참고: [Supabase AI Semantic Search](https://supabase.com/docs/guides/ai/semantic-search), [Supabase Vector Columns](https://supabase.com/docs/guides/ai/vector-columns), [Supabase Realtime](https://supabase.com/docs/guides/realtime), [Supabase Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security)

### 3.3 대화형 AI 트렌드 스터디 코치 플러그인

**사용자 가치**

웹앱을 직접 열지 않아도 ChatGPT/Codex 대화에서 트렌드를 찾고, 자료를 저장하고, 스터디를 만들고, 진행 상황을 확인할 수 있다. 해커톤 시연에서 차별화가 가장 잘 드러난다.

**기능 흐름**

1. 사용자가 “이번 주 에이전트 관련 중요 뉴스 5개와 토론 질문을 만들어줘”라고 요청한다.
2. MCP 도구가 Supabase의 검증된 기사와 북마크를 검색한다.
3. Skill이 출처 포함 요약, 중요도 판단, 질문 생성 순서를 규정한다.
4. Plugin이 결과를 카드/인터랙티브 뷰로 보여준다.
5. 선택한 글로 스터디를 생성해 Supabase에 저장한다.
6. 딥링크로 웹 스터디룸을 연다.

**권장 MCP 도구**

- `search_trends(query, date_range, topics)`
- `save_article(article_id)`
- `create_study_session(article_ids, duration, difficulty)`
- `get_study_progress(session_id)`

**기술 역할**

| 기술 | 역할 |
|---|---|
| 웹페이지 | 전체 대시보드·스터디 편집 화면과 플러그인 딥링크 |
| 배포 | Sites로 웹 UI와 Site MCP 서버를 함께 배포 |
| Supabase | 플러그인과 웹앱이 공유하는 데이터·권한 계층 |
| Skill | 도구 호출 순서와 출처 표시 규칙 |
| Plugin | MCP 도구, 대화 내 인터랙티브 뷰, 딥링크 제공 |

**MVP 범위**

- MCP 도구 3개: 검색, 저장, 스터디 생성
- `trend-study-coach` Skill 1개
- 대화 내 결과 카드 1개와 웹 스터디룸 딥링크
- 조회는 즉시 실행하고 생성·수정은 사용자 확인 후 실행
- 개인 계정 1개 또는 초대된 소규모 팀만 지원

**난이도와 리스크**

- 난이도: 중상
- 가장 큰 리스크는 웹 사용자와 플러그인 사용자의 신원 연결이므로 단일 사용자 또는 초대 팀으로 범위를 제한한다.
- MCP 반환 스키마를 작고 안정적으로 유지한다.
- 웹앱과 플러그인이 같은 도메인 모델과 백엔드를 공유하게 한다.
- Supabase는 HTTP API/client를 통해 연결하고 쓰기 작업에는 명시적인 확인 흐름을 둔다.

공식 참고: [OpenAI MCP Extensions 사양](https://github.com/openai/mcp-extensions/blob/main/docs/spec.md), [OpenAI MCP Extensions 저장소](https://github.com/openai/mcp-extensions), [Supabase Data API 보안](https://supabase.com/docs/guides/api/securing-your-api)

## 4. 해커톤 구현 우선순위

1. **자동 트렌드 피드:** 실제 시연 데이터를 확보하고 출처 기반 카드와 필터를 완성한다.
2. **AI 스터디룸:** 선택한 글 3~5개로 통합 요약, 질문, 퀴즈, 완료 체크를 생성한다.
3. **스터디 코치 플러그인:** 같은 백엔드를 호출하는 검색·저장·스터디 생성 도구를 붙인다.

### 추천 데모 시나리오

1. Supabase Cron/Edge Function이 공식 소스에서 새 AI 정보를 가져온다.
2. 대시보드에서 “AI Agent” 태그로 필터링하고 기사 3개를 선택한다.
3. 각 카드에서 출처·날짜·3줄 요약을 확인한다.
4. “30분 스터디 만들기”를 눌러 통합 요약, 토론 질문 3개, 퀴즈 5개를 생성한다.
5. 팀원이 메모와 완료 상태를 남긴다.
6. 대화형 플러그인에서 “오늘 스터디 시작해줘”라고 요청해 같은 데이터와 진행률을 불러온다.

### 해커톤 성공 기준

- 공식/API 기반 소스 3종에서 실제 데이터가 들어온다.
- 모든 요약 카드와 퀴즈에 원문 링크가 남는다.
- 한 사용자가 기사 선택부터 스터디 생성까지 1분 안에 완료한다.
- 팀원별 읽음/완료 상태가 저장된다.
- 플러그인이 검색·저장·스터디 생성 중 최소 3개 동작을 안정적으로 수행한다.
- 공개 테이블에 RLS가 적용되고 비밀 키가 클라이언트에 노출되지 않는다.

## 최종 제안

기능을 넓게 펼치기보다 **“출처를 믿을 수 있는 AI 트렌드 수집 → 즉시 스터디 전환”**을 제품의 한 문장 가치로 삼는 편이 좋다. 첫 데모에서는 자동 수집, 출처 표시, 3줄 요약, 스터디 생성, 팀 완료 체크를 완성하고, 플러그인은 같은 기능을 대화에서 호출하는 얇은 인터페이스로 구현하면 기술적 완성도와 시연 효과를 함께 확보할 수 있다.
